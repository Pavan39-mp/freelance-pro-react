# ABSTRACT

Freelancers commonly manage clients, project commitments, task deadlines, communication, meetings, files, work hours, and payments using disconnected tools. This fragmentation makes it difficult to maintain a consistent view of project status, establish responsibility between a freelancer and client, identify schedule risk, and connect completed work with invoicing. FreelancePro – Freelancer Productivity Platform addresses this problem through a centralized, role-based web application for freelancers and their clients.

FreelancePro is implemented as a full-stack MERN application. The frontend uses React, Vite, Tailwind CSS, React Router, Axios, Context API, Framer Motion, Recharts, React Hot Toast, Lucide React, and date-fns. The backend uses Node.js and Express.js, while MongoDB Atlas is accessed through Mongoose ODM. Authentication is based on JSON Web Tokens and password hashing. Protected routes, role-based authorization, Helmet, CORS controls, and rate limiting support application security.

The system provides distinct Freelancer and Client workspaces. Freelancers can manage CRM clients, projects, tasks, deadlines, meetings, notes, files, time tracking, analytics, notifications, project requests, messages, profile information, and settings. Clients can discover public freelancer profiles, send project requests, communicate about requests, monitor accepted projects and tasks, schedule or view meetings, create payment documents, record payments, and manage their own profile and settings. When a targeted project request is accepted by the selected freelancer, the backend creates a project linked to the request, client, and freelancer, thereby preserving the relationship throughout project execution.

The platform also derives productivity-oriented information from operational data. Freelancer productivity is calculated from task completion, dated delivery evidence, completed projects, and verified feedback where available. Project health combines task completion, overdue work, blocked tasks, and deadline proximity. Client reliability is derived only when sufficient project, invoice, payment, or meeting evidence exists; otherwise, the system explicitly indicates that the score is still being built. Rule-based project insights explain pending tasks and deadline conditions without depending on an external artificial-intelligence service.

Testing covers registration, role-aware login, protected navigation, project-request transitions, automatic project creation, deadline enforcement during task creation, client project visibility, messaging, meetings, notifications, invoices, profile settings, and logout. The resulting application demonstrates how a unified role-aware platform can reduce operational fragmentation while preserving clear authorization boundaries between freelancer-owned and client-accessible data.
